# CH32V208WBU6-EVT-R0-1v4 测试报告

## 一、测试概述

- **测试板卡** :CH32V208WBU6-EVT-R0-1v

- **测试目标**  验证使用 RuyiSDK 统一工具链管理，在 CH32V208 上进行 Hello World 编译、烧录和运行的完整流程

## 二、测试执行过程

### 2.1 安装 RuyiSDK 包管理器

```bash
sudo apt update
wget https://mirror.iscas.ac.cn/ruyisdk/ruyi/tags/0.50.0/ruyi-0.50.0.amd64
chmod +x ./ruyi-0.50.0.amd64
sudo cp -v ./ruyi-0.50.0.amd64 /usr/local/bin/ruyi
```

| 步骤                   | 结果              |
| ---------------------- | ----------------- |
| 下载 ruyi-0.50.0.amd64 | ✅ 成功 (37.23 MB) |
| 添加可执行权限         | ✅ 成功            |
| 复制到 /usr/local/bin  | ✅ 成功            |

### 2.2 安装 GCC 和 LLVM 工具链

```bash
ruyi update
ruyi install gnu-plct llvm-plct
```

| 步骤                     | 结果   |
| ------------------------ | ------ |
| `ruyi update`            | ✅ 成功 |
| `ruyi install gnu-plct`  | ✅ 成功 |
| `ruyi install llvm-plct` | ✅ 成功 |

### 2.3 创建并激活虚拟环境

```bash
ruyi venv --toolchain gnu-plct generic gcc-env
. gcc-env/bin/ruyi-activate
```

| 步骤         | 结果   |
| ------------ | ------ |
| 创建虚拟环境 | ✅ 成功 |
| 激活虚拟环境 | ✅ 成功 |

### 2.4 安装 PlatformIO Core

```bash
pipx ensurepath
pipx install platformio
pio --version
```

| 步骤                 | 结果                |
| -------------------- | ------------------- |
| pipx 安装 PlatformIO | ✅ 成功              |
| `pio --version`      | ✅ 成功 (版本 6.x.x) |

### 2.5 配置 PlatformIO 环境

```bash
pio platform install https://github.com/Community-PIO-CH32V/platform-ch32v.git
```

| 步骤                 | 结果                     |
| -------------------- | ------------------------ |
| 安装 CH32V 平台支持  | ✅ 成功                   |
| 安装 toolchain-riscv | ✅ 成功 (1.120200.220829) |
| 安装 tool-wchisp     | ✅ 成功 (0.23.240914)     |
| 安装 tool-minichlink | ✅ 成功 (0.1.0)           |
| 安装 tool-wlink      | ✅ 成功 (0.23.241116)     |

### 2.6 配置 udev 规则

```bash
curl -fsSL https://raw.githubusercontent.com/platformio/platformio-core/develop/platformio/assets/system/99-platformio-udev.rules | sudo tee /etc/udev/rules.d/99-platformio-udev.rules
cat << EOF | sudo tee -a /etc/udev/rules.d/99-platformio-udev.rules
SUBSYSTEM=="usb", ATTR{idVendor}="1a86", ATTR{idProduct}=="8010", GROUP="plugdev"
SUBSYSTEM=="usb", ATTR{idVendor}="4348", ATTR{idProduct}=="55e0", GROUP="plugdev"
SUBSYSTEM=="usb", ATTR{idVendor}="1a86", ATTR{idProduct}=="8012", GROUP="plugdev"
EOF
sudo udevadm control --reload-rules
sudo udevadm trigger
```

| 步骤           | 结果   |
| -------------- | ------ |
| 添加 udev 规则 | ✅ 成功 |
| 重载 udev 规则 | ✅ 成功 |
| 触发设备扫描   | ✅ 成功 |

### 2.7 安装 wlink 工具

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source ~/.cargo/env
cargo install wlink
wlink --version
```

| 步骤                  | 结果   |
| --------------------- | ------ |
| 安装 Rust             | ✅ 成功 |
| `cargo install wlink` | ✅ 成功 |
| `wlink --version`     | ✅ 成功 |

### 2.8 创建 PlatformIO 项目

```bash
pio project init
```

创建 `platformio.ini`：

```ini
[env:ch32v]
platform = ch32v
board = genericCH32V208WBU6
monitor_speed = 115200
upload_protocol = minichlink
```

### 2.9 编写 Hello World 代码

```c
cat > hello.c << 'EOF'
#include <stdio.h>

int main() {
    printf("Hello, World!\n");
    return 0;
}
EOF
    
riscv64-plct-linux-gnu-gcc hello.c -o hello-gcc
```

| 固件烧录 (WCH-Link)               | ❌    | 出现多种通信错误                                             |
| `ruyi device provision`           | ❌    | 仅提供 documentation-only，无可用镜像                        |
| `ruyi extract wch-ch32v20x-evt`   | ❌    | SDK 下载后 SHA256 校验失败                                   |

---

## 四、核心问题分析

### 4.1 RuyiSDK 对 CH32V208 的支持不足

- `ruyi device provision` 中 CH32V208 EVB 的配置**仅有 documentation-only**，该设备尚未获得预构建系统镜像或自动化 SDK 安装支持。
- `ruyi extract wch-ch32v20x-evt` 下载的官方 SDK 压缩包校验和与元数据不符，自动获取流程失败。

### 4.2 PlatformIO 平台依赖缺失

- `platform-ch32v` 安装后，其依赖的 `framework-wch-noneos-sdk` 未自动拉取。
- 手动获取 SDK 的尝试全部失败（GitHub 404、WCH 官网校验失败）。
- 缺少 SDK 导致：
  - `ch32v20x.h` 头文件找不到
  - 启动文件（startup）缺失
  - 链接脚本（Link.ld）缺失
  - 编译出的 `.elf` 固件大小为 0（无有效代码）

### 4.3 烧录工具与设备通信障碍

- **模式问题**：WCH-Link 默认可能为 ARM 模式，需手动切换至 RV 模式（RISC-V），但文档未详述方法。
- **通信问题**：OpenOCD 或 `minichlink` 均出现连接失败，涉及权限、设备节点或配置参数问题。
- 即使在 `lsusb` 中识别到 WCH-Link，PlatformIO 仍无法正常通信。

### 4.4 工具链命名与环境变量

- `ruyi venv` 激活后，`riscv64-unknown-elf-gcc` 不存在。
- 实际可用的是 `riscv64-plct-linux-gnu-gcc`，但该工具链用于 Linux 应用程序编译，**不适用于裸机嵌入式开发**（缺少裸机库和启动文件）。

### 4.5 `ruyi extract` 校验失败

- Ruyi 软件包元数据中记录的 SHA256 值与 WCH 官网实际提供的 zip 包不匹配。
- 上游源文件可能已更新，但 Ruyi 的元数据未同步更新。

---

## 五、总体评价

当前 **RuyiSDK 无法为 CH32V208WBU6 提供一套开箱即用的开发体验**。尽管基础工具链（GCC/LLVM）和 PlatformIO 核心可以安装，但关键的芯片支持包（SDK）、烧录工具集成及设备配置均存在缺口，导致无法完成 "编写代码 → 编译 → 烧录 → 运行" 的完整闭环。

### 现状总结

```
编写代码 ✅  →  编译 ❌  →  烧录 ❌  →  运行 ❌
                ↑
         缺少 SDK / 头文件
         工具链不匹配
         校验失败无法自动获取
```

---

## 六、测试结论

本次测试清晰地暴露了 RuyiSDK 在**非主流 RISC-V MCU（特别是使用自定义调试协议的设备）** 支持上的成熟度不足。

**CH32V208WBU6-EVT-R0-1v4 当前无法通过 RuyiSDK 实现完整的 "Hello World" 测试闭环**。主要障碍包括：

1. ❌ 裸机工具链缺失
2. ❌ 官方 SDK 无法通过 Ruyi 自动获取
3. ❌ 烧录工具与 WCH-Link 通信存在多重障碍
4. ❌ `device provision` 仅提供文档而非可用镜像

如有进一步测试需求，建议优先使用 MounRiver Studio IDE + 官方 EVT 包，待 RuyiSDK 对 CH32V 系列的支持完善后再行迁移。
